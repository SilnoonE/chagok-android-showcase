# 개발 과정과 판단

별도 개발 채팅인 **차곡 : 주유부터 정비까지**의 요청·완료 기록과 현재 프로젝트의 README·테스트 문서를 함께 확인했습니다. 아래 내용은 그 자료를 공개 가능한 범위로 정리한 것입니다.

## 첫차를 관리하는 사람의 흐름

첫차 관리에서 자주 반복하는 일인 주유 기록, 정비 기록, 월 유지비 확인, 다음 관리 시점을 한 앱에 모았습니다. 처음부터 차량 연결이나 자동 추적을 붙이기보다 사용자가 기록한 값의 의미를 일관되게 유지하는 데 집중했습니다.

## 구현 선택

| 문제 | 선택 | 고려한 점 |
|---|---|---|
| 월 유지비의 의미가 모호해짐 | 실제 결제일과 결제금액 기준 합산 | 보험·세금도 결제 월에 전액 반영 |
| 과거 기록을 넣으면 현재 거리가 바뀜 | 현재 주행거리의 자동 하락 방지 | 기록 이력과 현재 차량 상태의 역할 구분 |
| 금액 계산 안정성 | 정수 Long 저장 | 소수점 금액 오차와 작은 정수 범위 회피 |
| 관리 시점이 날짜·거리로 다름 | 두 기준 중 먼저 도달하는 일정 표시 | 완료 일정은 임박 표시에서 제외 |
| 백업 복원 중 부분 교체 | 검증 후 트랜잭션 교체 | 실패했을 때 기존 데이터 보존 |
| 파일 접근 범위 | 시스템 문서 선택기 | 광범위한 저장소 권한 없이 파일 선택 |

## 입력과 화면 개선

차량 등록 뒤 바로 주유·정비를 기록할 수 있도록 입력 시트를 사용했습니다. 기존 기록의 이름·금액·장소를 다시 불러오는 흐름과 현재 주행거리만 빠르게 고치는 동작을 추가했습니다.

월 예산은 단순 잔액뿐 아니라 오늘을 포함한 월말까지의 남은 일수로 나눈 하루 예산을 보여 줍니다. 다른 달을 보고 있을 때 현재 달의 하루 예산처럼 표시하지 않도록 계산 범위를 정했습니다.

후속 개발 대화에서는 하단 내비게이션 아래 빈 공간과 광고 영역 사이 간격을 줄이는 요청이 있었습니다. 시스템 하단 여백과 내비게이션 높이를 조정한 기록을 확인했습니다. 배포 상태는 바뀔 수 있어 이 문서를 정식 출시 완료 증빙으로 사용하지 않습니다.

## 후속 검토

실물 휴대폰과 큰 글꼴에서 입력·하단 메뉴를 확인하고, 장시간 절전·재부팅 상황의 알림을 추가 검증할 필요가 있습니다. 여러 차량, 영수증 OCR, 클라우드 동기화는 현재 구현과 분리해서 검토할 확장 항목입니다.

공개 저장소는 정리된 첫 스냅샷부터 시작합니다. 이전 대화의 개발 단계를 실제 과거 Git 커밋처럼 구성하지 않았습니다.
